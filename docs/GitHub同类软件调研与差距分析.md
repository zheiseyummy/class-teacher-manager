# GitHub 同类软件调研与差距分析

> 调研日期：2026-08-19
> 调研目的：借鉴成熟项目的产品结构和数据设计，完善本地离线版班主任综合管理系统。本文只作为后续开发决策依据，不表示要照搬学校级管理平台的全部功能。

## 一、产品定位结论

本项目应继续定位为：**面向初中班主任和任课教师的 Windows 本地办公工具**。

核心价值是：

1. 无需服务器和网络，安装后即可使用。
2. 以 Excel 导入为主要数据入口，减少重复录入。
3. 聚焦成绩对比、学生个体分析、六学期综合素质评价和期末档案输出。
4. 数据由教师本人掌握，可按学期完整备份和恢复。
5. 功能和界面适合日常高频办公，不扩张为复杂校务 ERP。

与 GitHub 上多数同类项目相比，本项目的差异化优势已经比较明确：

- 原生 Windows 桌面体验，而不是要求教师部署 Web 服务。
- SQLite 本地数据库，离线可用。
- 已覆盖学生、成绩、六学期五维综评、请假考勤、德育、课程表日历和备份。
- 综合素质模块贴合本地实际规则：五个维度、六个学期、A/B/C/N/A、九下最终名单、比例分配、教师复核与锁定。
- 支持按班级管理和面向教育局底册的 Excel 工作流。

## 三、当前已经做得较好的部分

根据现有代码和项目文档，以下能力已经形成可用基础：

1. 模块化的 PySide6 + SQLAlchemy + SQLite 桌面框架。
2. 多班级学生档案、多个联系人、搜索、Excel 导入导出。
3. 六学期、五维度综合素质记录及 N/A 缺失值处理。
4. 九下汇总、维度累计、五维总分、班级排名、ABC 分配、教师复核和锁定流程。
5. 多次考试、九门学科、变化满分、班级/年级排名及学生、班级、学科趋势数据。
6. 请假考勤、德育活动、课程表、日历、本地 ZIP 备份与恢复。
7. 今日工作台和近期成绩波动学生预览。

这些能力已经超过多数简单的“学生管理课程作业”仓库。下一阶段的重点应从继续堆模块，转为把成绩工作流做深、把跨学期数据基础做稳。

## 四、主要不足与优先级

### P0：下一阶段必须先解决

#### 1. 学年、学期和班级历史尚未统一

目前课程表、考试和综合素质评价分别使用自己的学期表示方式；学生只保存当前班级。长期使用后，升年级、换班、转入转出会影响历史统计的可信度。

建议增加统一的“学年/学期”主数据，并建立学生就读历史：

- 每次考试、综评、请假和课程表都关联同一学期记录。
- 学生换班后，旧考试仍保留当时的班级归属。
- 新学期默认沿用原班名单；跨学年时原班整体自动升年级。
- 支持在当前班级新增、转入和移出学生，所有变化均保留历史。
- 学期结束后可锁定并归档。

#### 2. 成绩 Excel 导入还不够稳健

成绩导入是教师最高频、风险最高的操作，目前最需要升级为完整导入向导：

- 导入前预览表头、学生匹配和科目识别结果。
- 支持保存“月考、期中、期末、教育局”等列映射方案。
- 明确显示未匹配学生、重复学号、缺考、空值、超满分和异常科目。
- 导入前确认各科满分与是否计入总分。
- 重复导入时选择跳过、覆盖或另存为新考试。
- 保存导入批次、原文件信息和错误清单。
- 支持撤销最近一次成绩导入。
- 补充旧版 `.xls` 文件支持。

#### 3. 不同考试之间缺少“可比性规则”

当科目、满分或参考人数变化时，直接比较总分容易误导。建议同时提供：

- 班级排名与年级排名变化，作为主要进退步依据。
- 单科得分率，用于跨满分比较。
- 同科在班级中的相对位置，用于偏科判断。
- 考试科目不一致时，明确提示“总分不可直接比较”。
- 缺考和未参加科目显示 N/A，不按 0 分处理。

#### 4. 进退步名单仍需成为正式工作流

- 阈值由教师输入，例如进步或退步 10 名、20 名。
- 班级排名和年级排名可分别设置。
- 自动生成“明显进步、明显退步、持续波动、偏科关注”名单。
- 从工作台名单可直接进入学生个体分析。
- 名单支持 Excel 导出。

### P1：紧随其后的核心完善

#### 5. 分析展示仍偏表格化

建议补充可交互图表，但不做装饰性大屏：

- 学生总分/排名趋势折线图。
- 各科得分率趋势图。
- 班级分数段和排名段分布。
- 学科均分、优秀率、及格率、低分率对比。
- 点击图表区间可下钻到对应学生名单。
- 用波动度识别“成绩不稳定”，用相对优势识别偏科。

#### 6. 缺少外部年级基准数据

用户已有“年级各科均分、四率对比”类 Excel。建议允许单独导入：

- 年级各科均分。
- 优秀率、及格率、低分率等统计。
- 各班对比数据。
- 分数线或等级线。

这样即使没有全年级每名学生的明细，也能完成班级与年级基准对比。

#### 7. 考试缺少确认、锁定和修订记录

建议采用“草稿 -> 已导入 -> 已确认 -> 已锁定”的状态：

- 锁定后避免误改。
- 需要纠错时执行“解锁/修订”，保留原因和时间。
- 分析和报告默认只使用已确认考试。

#### 8. 期末输出还不完整

优先增加：

- 班级成绩分析 Excel。
- 单个学生本学期成绩与趋势报告。
- 本学期成绩 + 综合素质联合档案。
- 六学期综合素质最终档案。
- PDF 打印版和可复核的 Excel 明细版。
- 学期归档 ZIP 内附清单，说明包含哪些数据库、报告和原始导入文件。

### P2：工程质量和长期维护

#### 9. 数据库升级方式需要版本化

目前应从零散兼容处理逐步迁移到正式数据库版本机制，确保旧电脑上的数据库可以稳定升级，不因增加字段而丢失数据。

#### 10. 需要统一的数据质量中心

集中显示并处理：

- 未匹配学生和重复学号。
- 学期缺失记录。
- 成绩超范围、缺考和异常空值。
- 综评缺失的学期/维度。
- 已锁定数据与待确认数据。

#### 11. 面向其他任课教师时缺少使用配置

暂时不必开发复杂账号权限，但应预留“教师资料、任教学科、常用班级、默认学期、导入模板”配置，方便把软件交给不同老师使用。

## 五、明确不建议增加的功能

以下功能虽然在大型开源系统中常见，但不符合当前产品定位：

- 招生、缴费、财务、图书、宿舍、校车和人事。
- 家长门户、学生登录、在线聊天和通知平台。
- 教学资源库、在线作业和试卷编辑器。
- 依赖服务器、Docker 或公网的多用户部署。
- 在数据量不足时给出升学概率或“AI 预测结论”。

这些功能会显著增加维护成本，却不能改善当前最重要的成绩导入、分析和期末输出体验。

## 六、建议的开发顺序

### 第 1 步：稳定跨学期数据基础

统一学年/学期，增加学生就读历史、考试状态和导入批次记录，并提供旧数据库升级方案。

### 第 2 步：重做成绩导入向导

完成预览、字段映射方案、满分确认、异常检查、导入结果和一键撤销，并支持 `.xls/.xlsx`。

### 第 3 步：完善成绩分析

增加可调阈值名单、得分率、偏科、波动度、班级/年级趋势图和外部四率基准导入。

### 第 4 步：完善期末报告

导出成绩分析、学生个体报告、成绩与综合素质联合档案，以及 PDF 打印版。

### 第 5 步：集中验收

使用真实的月考、期中、期末、年级均分/四率和六学期综评底册，完成导入、复核、锁定、报告、备份与恢复的整套演练。

## 七、已确认与待确认事项

### 已确认

1. **班级自动升年级**：新学期默认沿用原班学生；进入新学年时，原班整体升入下一年级。
2. **允许调整班级人员**：可新增、转入或移出学生。界面中的“移出”只结束该生在当前班级的就读关系，不删除其历史成绩、综合素质评价和其他档案。
3. **毕业处理**：初三完成后班级进入“已毕业/已归档”状态，不自动创建高中班级。
4. **进退步依据**：主要比较班级排名和年级排名；考试录入时可设置各科满分，单科用得分率辅助分析。
5. **缺失科目处理**：未参加考试或该次考试未设置的科目显示 N/A，不作为 0 分参与计算。
6. **成绩导入流程**：采用“先预览、再确认导入”。预览阶段不写入数据库，教师确认学生匹配、科目、满分及异常记录后才正式保存。
7. **导入批次撤销**：每次导入保存为独立批次；考试锁定前允许一键撤销整个批次，锁定后不可直接撤销。
8. **教师独立使用**：每位教师单独安装并使用自己的本地数据库和备份，不在同一套数据中切换教师。
9. **不开发权限系统**：不增加账号登录和复杂权限；只提供教师姓名、任教学科、常用班级、默认学期和导入模板等本地设置。
10. **班级自动命名**：跨学年时，标准班名按“初一1班 -> 初二1班 -> 初三1班”自动递进；升年级预览中允许逐班修改新班名。初三班毕业后只归档，不继续自动改名。
11. **升年级班级范围**：新学期向导支持勾选一个或多个班级，默认选中全部在读班级，并逐班预览名称、人数和人员变化。跳过的班级只停止延续，不删除其历史档案。
12. **课程表复制**：创建新学期时提供“复制上一学期课程表作为草稿”选项，默认不勾选。复制结果归属于新学期并可单独修改，旧学期课程表保持为历史记录。
13. **学期更新恢复点**：每次创建新学期或执行整班升年级前，强制自动生成一份本地 ZIP 备份；备份名称包含目标学期和创建时间，供误操作后恢复。
14. **底部版本信息**：左侧菜单底部显示统一的软件版本号。版本号同时用于备份清单、导出报告和后续 EXE 文件信息，避免各处显示不一致。
15. **个人标记**：版本号下方预留一行尺寸更小、颜色更淡的个人标记。标记内容由本地教师设置提供，方便每位独立使用软件的教师自行修改。
16. **教师信息设置**：增加轻量的本地教师资料设置，不单独占用左侧模块。首次使用时引导填写，之后可点击顶部问候语或底部个人标记修改。

教师信息建议包含：

- 教师姓名（必填）。
- 学校名称（选填，可用于导出报告标题）。
- 任教学科（可多选并支持自定义）。
- 常用班级（从已有教学班中多选）。
- 默认学年与学期。
- 自定义个人标记（选填）；未填写时自动显示“姓名老师 · 个人教学工作台”。

教师信息只保存在当前软件的本地数据库中，不包含账号、密码、身份证号和联系电话，也不用于多教师登录切换。

17. **版本规划**：`v1.0.0` 正式版已完成发布构建。版本号由一个统一位置维护，并同步用于界面底部、备份清单、导出报告和 EXE 文件信息。

建议的新学期向导将先显示升年级预览，教师确认后再执行；误录且尚无任何关联数据的学生，才允许执行永久删除。

### 待确认

当前影响下一阶段开发的关键问题均已确认。新需求可在对应模块开始前继续逐项确认。

## 八、当前结论

本项目不缺模块，真正的短板集中在三个地方：

1. 跨学期、跨班级的历史数据关系还不够稳定。
2. Excel 成绩导入缺少预览、映射、异常处理和撤销闭环。
3. 成绩分析还没有形成“自动发现问题学生 -> 查看原因 -> 导出名单/报告”的完整工作流。

建议下一项正式开发任务从“统一学期与学生历史 + 成绩导入向导”开始。这两项打稳后，趋势图、偏科分析和期末报告才能可靠地建立在同一份数据上。
